# Financial AI Agent

基于 FastAPI、Vue 3、LangChain 与自研编排器的金融分析 Agent，设计来源为 [金融分析 AI Agent 方案](3、Agent项目-基于LLM的金融分析AI+Agent.pdf)（92 页）。

**当前可用：模型与工具循环、多轮历史、多 Agent 依赖执行、报告生成/保存/阅读/下载，以及 SQLite/PostgreSQL 共用业务存储。PostgreSQL 适配与迁移代码已实现，但本机连接不可用，真实数据库集成尚未验收；RAG 本地入库、混合检索和引用链已接通；已接入腾讯证券/东方财富公开 A 股数据；Embedding 服务及真实资料验收见下文历史记录。**

更新日期：2026-10-09。本文区分设计目标、实际实现与待办；有类、表定义或页面不等于业务已接通。优先级是根据当前代码缺口和功能依赖重新制定的实施顺序，并非 PDF 原文的优先级。PDF 中的代码、示例命令和架构描述作为参考，不作为已验证结果。

### 业务数据库

设计依据：§2、§6.4、§8.2。为兼容已有 SQLite 历史，当前实现采用 **同步 SQLAlchemy + psycopg**，异步执行链中的数据库操作交给线程执行，普通读取接口由 FastAPI 线程池执行；未使用原计划的异步 Session。默认仍使用 SQLite，不自动切换或覆盖 `.env`。

- [x] `storage/schema.py` 统一定义会话、完整消息轮次、Agent 运行、报告及文档元数据表；schema v1 做增量初始化。
- [x] `storage/conversations.py` 管理连接和事务；成功的运行、对话轮次和报告正文在同一事务提交，失败会回滚并记录错误。
- [x] SQLite 历史迁移命令使用源文件快照、保留会话 ID/标题/归档/消息；相同记录跳过，内容冲突则整次导入回滚。
- [x] RAG 入库保存正文、元数据及索引状态；已提供版本发布和手动重试，跨库对账与孤立向量回收仍待补齐（P1-C）。
- [x] 服务重启将未完成运行、报告及文档索引标记为失败；完成的报告保留，不能将中断标记为成功。
- [x] 本地 SQLite 验证旧表升级、迁移幂等性、冲突回滚、事务回滚和重开数据库读取。
PostgreSQL 实例验收见 P1-B，多用户权限与跨进程协调见 P4；当前仅支持单用户、单 worker，不使用 Redis 任务队列。

`models/database.py` 和 `infra/init.sql` 保留 PDF 设计定义，**当前业务初始化以 `storage/schema.py` 和迁移命令为准**，不将两套表混用。报告和运行记录独立保留，删除聊天会话不会删除报告；报告需在报告中心单独删除。

2026-10-08 实现说明：文档正文和当前版本保存在业务库 payload 中；新向量写入成功后才发布版本，检索只读取已发布版本，更新失败保留旧版。删除先隐藏文档再清理向量，失败可重试删除。跨库清理失败可能留下不可检索的孤立向量，暂无后台回收任务。当前为单 worker、小规模知识库，BM25 每次读取本地候选文本。

接口：`POST /rag/knowledge/upload`（multipart：file、title、category、metadata JSON，可传 doc_id 更新）、`GET /rag/knowledge/documents`、`GET/DELETE /rag/knowledge/documents/{id}`、`POST /rag/knowledge/documents/{id}/reindex`、`GET /rag/knowledge/stats`、`POST /rag/query`；均位于 `/api/v1`。保留 `/rag/knowledge/add` 文本入口。日期过滤示例：`{"stock_code":"600519","disclosure_date":{"$gte":"2025-01-01","$lte":"2026-12-31"}}`。

更换 Embedding 配置并重启后，在页面逐份点击“重新索引”，原文从业务库读取；新集合不混用旧向量。旧版本仅通过 add 接口保存元数据而没有原文的文档需要重新上传。2026-10-08 真实 Embedding 冒烟请求返回 `APIConnectionError`，没有宣称连接成功；首批授权资料尚未导入。

已验证本地 Chroma/SQLite 与模拟 Embedding 的生命周期和检索。真实服务、真实资料及完整浏览器上传流程见 P0-B；质量与恢复增强见 P1-C。

**验收：** 相同解析内容、标题、分类和元数据在同一索引配置下重复导入不重复计数；更新/删除影响检索结果；按公司和时间过滤有效；真实问题回答能定位到来源，证据不足时明确说明。

说明：当前实际向量存储使用 `rag/knowledge_base.py` 的 Chroma；`core/vectorstore.py` 仍有占位实现。改配置为 Milvus 不代表已完成切换。

## 4. 历史对话与数据准备

聊天页左侧支持新建、切换、归档、恢复和永久删除（需确认）。归档对话可查看，恢复后才能续聊。首轮成功后用问题前 40 个字符生成标题。

完整成功轮次保存到 `backend/data/conversations.sqlite3`，首次使用自动创建；根目录 `.env` 可用 `CHAT_HISTORY_DB` 指定绝对路径。浏览器只记住当前会话 ID。完整历史不受模型最近 10 轮上下文限制，失败请求不保存；旧版本仅在内存中的对话无法自动找回。当前为本地单用户方案，会话锁不提供多进程协调。

接口：`GET/POST /api/v1/conversations`，`GET/DELETE /api/v1/conversations/{id}`，`PATCH /api/v1/conversations/{id}`（`{"archived": true}` 或 `false`）；归档列表使用 `?archived=true`。

继续开发所需资源：

- DeepSeek 与 Embedding 服务的有效密钥、模型权限及额度。密钥只放根目录 `.env`，不复制进文档或测试输出。
- 至少一个金融数据源及访问权限，明确市场范围、历史区间和更新频率。
- 首批 3～5 家公司的年报/公告及来源信息，可从交易所、巨潮资讯等公开披露渠道收集；研报需确认使用授权。
- 可用于集成测试的 PostgreSQL 实例；Redis 在实际接入队列/协调时另行准备。配置地址不等于服务已就绪。
- 对外部署或机器人渠道所需的域名、环境和应用凭据。

### 业务存储配置与历史迁移

默认 `BUSINESS_STORAGE=sqlite`，继续使用 `CHAT_HISTORY_DB` 指定的本地数据库，并自动添加业务表。已补充 psycopg 驱动依赖，无需为本地使用额外启动 PostgreSQL。

切换 PostgreSQL 前先停止后端、备份 SQLite，在根目录 `.env` 配置：

```dotenv
BUSINESS_STORAGE=postgresql
DATABASE_URL=postgresql+psycopg://USER:PASSWORD@HOST:5432/financial_agent
```

原有 `postgresql+asyncpg://` 地址也会转换为 psycopg 驱动；密码等信息不要粘贴进 README。确认数据库已创建且连接用户有建表权限，再执行：

```bash
cd /Users/ling/project/backend
.venv/bin/python -m app.storage.migrate
.venv/bin/python -m app.storage.migrate --import-sqlite /Users/ling/project/backend/data/conversations.sqlite3
```

迁移命令只迁移历史会话及消息，不合并两个数据库的报告/运行记录。迁移源文件不变；目标会话相同则跳过，不同则失败并回滚。切换前后核对会话数、归档状态和消息正文。若需回退，停止后端、恢复 `BUSINESS_STORAGE=sqlite` 并使用保留的原库；切换后 PostgreSQL 新产生的数据不会自动回写 SQLite。

当前 schema 只有 v1，采用版本记录和增量建表，无破坏性降级命令；后续结构变更需要新增迁移版本。真实 PostgreSQL 测试使用独立临时 schema，执行完自动清理，需要测试用户具有建 schema 权限：

```bash
cd /Users/ling/project/backend
# 通过环境设置 TEST_DATABASE_URL 为专用测试数据库连接，再执行：
.venv/bin/python -m pytest tests/test_postgres_storage.py -q
```

不设置 `TEST_DATABASE_URL` 时，该集成测试明确跳过。此前连接检查不可用，本次文档更新未重新检测连接；SQLite 测试通过不能替代 PostgreSQL 验收。
